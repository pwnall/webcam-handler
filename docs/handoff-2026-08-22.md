**The dependency paths, because they decide the shape of the work.**

- `h2` is reached through `hyper 1.11.0`, from `axum 0.8.9`, `hyper-util 0.1.20` and
  `jsonrpsee-server 0.26.0`, all into `webcam-handler-daemon`. A `cargo update -p h2` is the
  smallest move and touches no direct dependency row, but §2.8's registry pins versions at adoption
  and `--locked` is used everywhere, so the lockfile change is the deliverable and
  `dependency-registry-sync.sh` should be run after it.
- `quick-xml` **and** `paste` both arrive through **`little_exif 0.6.23`**, and `quick-xml` reaches
  the shipped binaries on normal edges — `little_exif` → `webcam-handler-imaging` →
  `webcam-handler-cli-core` → `webcam-handler-cli` — rather than dev-only. Checked with
  `cargo tree -i quick-xml -e normal`.
- That makes this **one problem wearing two advisory numbers**, and it lands on a trigger the plan
  already carries: docs/13's post-plan trigger table has *"Re-check PF:16 against `little_exif`"*
  on any `little_exif` bump (D6, PF:16). A newer `little_exif` is the likely fix for three of the

- `paste` has no upgrade at all, so if a newer `little_exif` has not dropped it the options are an

## Then: the mutation floor

`just mutants` has **not** completed a run this session, and the reason is worth knowing before you
start one.

- It now **refuses to start** unless the checkout is committed and the commit is on a remote
  (note **N348**). That is deliberate: a run is hours, and hours spent on work that exists only on
  this machine is how the work is lost. `just mutants-iterate` is exempt and is the triage mode.
- Its build trees are under **`target/wchm`** (notes **N347**, and N347's 2026-08-22 amendment).
  Not `/tmp`: that is a 16 GiB tmpfs on this host, and a run that fills it takes the machine.
  Not `target/wch-scratch/…` either — that path is 74 bytes, `mutants.sh` exports the build root as
  `$TMPDIR`, `TempRuntimeDir` builds socket paths under `$TMPDIR` on purpose, and 74 + 35 = 109
  against `sun_path`'s 107. The floor died inside its own baseline with `File name too long` and
  reported a red baseline in an unmutated tree.
- Expect roughly **2h23 at eight jobs** — that is N251's measured on-disk figure, and it supersedes
  E7's "7×" which several documents had been quoting as current until this session.
- N251's standing caveat applies: at the default job count a **survivor it reports is real**, but an
  **absence of survivors is not proof** — under load the floor both hides survivors and deletes true
  acceptances. `WCH_MUTANTS_JOBS=1` is the believable setting at 13–19 h, and the default remains an
  open owner ruling in docs/13's trigger table.

The order the owner asked for: **advisories first, CI green, then the floor.** On the evidence
above that is now three things before the floor — the four advisories, the kernel string in
`facade_equivalence`, and whatever the runner finds once it gets past that test, since no Actions
run has ever reached the end of this suite.

## What this session learned, that the next one should not re-learn

- **A green local `just ci` and a green runner are two claims, and nothing in this tree reconciled
  them.** Actions had been red on every push since 2026-08-19 — twelve runs — on a build
  precondition (N236) that the runner had never satisfied, and it was invisible from a host with
  newer kernel headers. If you change anything that a *host* supplies, ask which host.
- **Moving a path means asking what else reads it.** Two of this session's own repairs broke
  something by moving one: the build root under `target/wch-scratch` pushed every Unix socket in the
  suite past `sun_path` by two bytes, because one job's `$TMPDIR` is every socket's parent.
- **The adversarial reader earns its place every time.** Across four batches it returned findings
  the authors had missed in every one — including three files in a single diff disagreeing about one
  fact, a new ban that was itself one spelling of the class, and a byte table that was wrong in
  every row because it counted a placeholder's characters. Do not skip it, and do not let it read
  only its own author's claims.
- **A count in prose is a claim something reconciles.** Sixteen of fifty-nine criterion rows stated
  something false about the tree; two documents disagreed about the same five rows; a note's
  arithmetic was reasoned from a diff rather than read from the tree. Run the count.
